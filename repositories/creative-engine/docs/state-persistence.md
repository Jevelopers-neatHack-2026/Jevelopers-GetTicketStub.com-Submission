# SQLite state persistence

The paired version adapter admits inspection repairs through the same per-database write queue used by version publication, telemetry outbox writes, and recovery. Adapter calls to `startInspection`, `recordRepairClaim`, `recordRepairOutcome`, `cancelInspection`, `getState`, and `isClaimCurrent` return promises and must be awaited. The runtime awaits these operations. Injected inspection-repair ports may still implement the same operations synchronously; the public port type accepts either form so existing integrations remain valid.

`recordRepairOutcomeInPublication` is synchronous by design. It records the repair result inside the active publication transaction, using the paired adapter's live owner fence. Call it only from that publication path; a direct call without the active owner is rejected. The standalone `createSqliteInspectionRepairController` also keeps its synchronous API. When another operation owns that database, standalone controller calls fail closed instead of waiting on the event loop.

Ordinary `getBrief` reads keep the supported backfill for a validated legacy brief whose history row is missing. The final synchronous dispatch fence disables that backfill for both `getBrief` and `isBriefUsable`, so missing or corrupt immutable history fails closed without a metadata write.

The adapter rejects a caller-owned `BEGIN` or `SAVEPOINT` transaction. It does not commit, roll back, or create a nested savepoint inside a transaction it does not own; rejection leaves the caller's transaction intact. Recovery joins database admission before changing repair state. Provider, Finance, and other external work must complete outside the SQLite write transaction.

The admission queue coordinates writers in this process that resolve to the same SQLite database. SQLite still supplies file locking across processes; this queue alone does not qualify full public API publication and recovery across independent processes. The overlap fixtures use injected offline provider, Finance, vision, and JEV ports, plus generated valid 16x16 PNG bytes that exercise the local native decoder. They do not call live providers, use actual GPT image output, or establish target-host behavior or full-format qualification.

## Installed public API process regression

`make check TARGET=versions MODE=mock` includes `tests/versions/public-process-lifecycle.test.mjs`. It packs the current source and installs the local tarball offline with lifecycle scripts disabled. Its child worker is copied outside the repository package and imports only public package subpaths. Nine independent processes share one SQLite database and object directory during a deterministic fixture journey:

- Publish a generated root and two explicit-parent edits, holding one real publication transaction while the other process reaches its usage-outbox `BEGIN` boundary. This boundary handshake does not itself assert native SQLite contention.
- Reopen in a new process, replay the exact immutable result without a provider call or reservation, and reject a changed request under the same action ID.
- Cancel a dispatched edit through another process, then retain the late provider usage and attempt identity while preventing a child version from becoming visible.
- Race two evidence claimers, hard-exit them with open databases, reclaim their records after lease expiry, reject old claim tokens, and acknowledge the new claims without redispatch.
- Independently reopen SQLite, check integrity and foreign keys, compare unchanged immutable rows and selected root, and rehash every visible artifact.

A separate five-process journey holds publication until the other process's native usage `BEGIN IMMEDIATE` throws SQLite BUSY/LOCKED after the configured timeout. It then verifies that the blocking publication is still open, releases it, and checks the existing failure behavior: retryable unavailability, no child publication or usage acceptance, and a held reservation with durable attempt, transport, and unknown-outcome evidence. A hard-exit claimant and replacement process recover that evidence; exact replay returns the retained failed job without another provider call or reservation. The missing usage remains unpersisted and unsettled, requiring reconciliation; the test does not manufacture a successful retry.

A third installed-consumer journey seeds two tenant namespaces in one real SQLite database, deliberately reusing project, brief, and action IDs. Public list and compare expose only the authorized namespace. Expired context, missing permission, forged tenant/project scope, foreign version references, malformed references and foreign or malformed cursors are rejected without provider work or changes to retained versions, selections, usage, outbox records or foreign rows. Deliberately corrupting one local artifact makes list, compare and restore fail closed; the public API uses its existing `failed` error code for a Store integrity error. Rejected restores may retain failed local jobs. After explicit fixture byte restoration and process reopen, valid restore changes only the selected pointer, and replay of the previously failed restore remains failed without any selection change. Every history operation makes zero provider calls and reservations. Trusted principals and authorization boundaries remain synthetic.

Run these regressions with `node --test tests/versions/public-process-lifecycle.test.mjs`. Set `CREATIVE_MULTIPROCESS_EVIDENCE_ROOT` to a fresh empty directory to retain separate `lifecycle`, `busy`, and `history-boundaries` directories containing the exact tarballs, installed consumers, databases, objects, command outputs, and per-worker receipts. Execution preserves inherited environment controls, including proxy and network preloads. The receipts include runtime, argv, PID, timing, exit status, stream hashes, environment variable names without their values, and an IPC transcript whose synthetic claim tokens are replaced with SHA-256 digests. The history summary includes per-case error, state and object-inventory hashes. Ordinary runs remove their temporary directories.

Provider output, usage and Finance responses are synthetic and explicitly labeled mock/simulated. The generated PNG bytes establish retained byte identity in this regression; native decoder coverage is provided by the separate PNG/JPEG/WebP inspection cases. These local process checks do not establish production-host durability, power-loss behavior, external account access or owner acceptance, and do not replace the original raw SQLite locking probe or the remaining release journey gates.
