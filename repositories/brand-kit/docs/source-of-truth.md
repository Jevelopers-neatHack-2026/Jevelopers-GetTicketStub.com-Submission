The full per-file record (type, source/output relation, canonical authority, owner role, approval and provenance status) is [`inventory/brand-inventory.json`](../inventory/brand-inventory.json); `make check-inventory` fails if it drifts from the tracked files. This integration starts from `main` at `3c48922b54bf0cc7d92bf9de1f59b1bd3cdad4a4` on 2026-10-12; exact candidate and merged revisions are recorded in the PR evidence. Historical baseline: `74bc86f`, then governance PR #17 at `00e4129`.

**Approval and provenance are unknown unless stated.** No file here is recorded as approved for release. README says the identity is not ratified; nothing in this index changes that. Rights, tool and prompt provenance for the images, and redistribution policy, are left `unknown` for [BK-06](https://github.com/Jevelopers-neatHack-2026/brand-kit/issues/7).

## Classifications

| Class | Meaning | Examples |
|---|---|---|
| `canonical-source` | Edit here | `tools/build_logos.py`, `tokens/tokens.json`, font files |
| `generated` | Produced by a tracked generator from a source; do not hand-edit | `logo/*.svg` (by `tools/build_logos.py`), `tokens/tokens.css` and the other token outputs (by `tools/build_tokens.py`) |
| `derived-manual` | Derived from a JSON authority but maintained by hand because no generator is tracked. Edit only to mirror the authority; drift is not machine-checked | none now (the token outputs were reclassified `generated` in BK-03A) |
| `guideline` | Human guidance and the brand board | `SPEC.md`, `docs/*.md`, `index.html` |
| `licence-provenance` | Required third-party licence or provenance document. An export candidate that must ship with the asset it covers; never discard it as reference material | `fonts/Fraunces-OFL.txt`, `fonts/InterTight-OFL.txt` |
| `reference-only` | Inspiration artwork; excluded from export | `references/*.webp` (rights unknown) |
| `release_class` | `candidate-unapproved`, `reference-only` or `internal`. None is approved. Source font notices do not authorize font distribution; the current policy forbids self-hosted fonts. | |

**Migration for `derived-manual`.** Done for the token outputs: `tools/build_tokens.py` is tracked, the outputs are `generated`, and the inventory records `generated_by` and `generated_from`. The same rule applies to any future hand-derived file.

## Iconography

**Current state: there is no approved reusable icon system.** The repository has no icon library or iconography guidance. `logo/favicon.svg` and `logo/app-icon.svg` are logo variants. The inline SVG illustrations in [`index.html`](../index.html) (for example the mute glyph) are reference/demo illustrations on the board only: not an icon set, not approved, not export candidates. Whatever UI icon implementation ships today is owned by the consumers (getticketstub.com and others), outside this repository's inventory. [`OWNERSHIP.md`](architecture/OWNERSHIP.md) lists "icon treatment" as a responsibility without a source.

**Future decision (unresolved, BK-02 with consumer owners).** Whether to create an owned icon family or style guidance here (owned guidance doc, an owned asset family, or staying consumer-owned) is not decided. No approval is inferred from this index.

## Checks

See [inventory checks](inventory-checks.md). `make check` runs inventory, local links, governance shape, provenance-register structure, token generation/parity, computed accessibility and the unit suites. Use the pinned Python environment in [asset exports](asset-exports.md) for the full suite. `make check-tokens-tailwind`, `make check-assets` and `make check-accessibility-browser` execute the additional actual toolchains.

`make check-guidelines`, also included in `make check`, uses
[`tools/check_guidelines.py`](../tools/check_guidelines.py) and the deliberately
maintained [`docs/guidelines-source-snapshot.json`](guidelines-source-snapshot.json)
to reject public-source drift, missing visible review labels and incomplete
claim/usage records. It verifies a local source snapshot, not product truth or
accountable approval; the [claim register](claims-register.md) retains those
missing inputs.

`make check-package` and `make check-consumers-local` require a clean committed candidate and exercise unapproved review archives. `make check-provenance`, `make package-brand`, `make check-consumers` and `make check-brand-release` retain the missing rights, decisions and named acceptance blockers. The aggregate records all leaf outcomes in a fresh output directory. Missing required cases never become passes; no check changes a foreign/global acceptance criterion.
