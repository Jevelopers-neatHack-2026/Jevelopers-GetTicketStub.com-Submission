# Concept generation source proposal

This document and `src/generation/concepts.mjs` define an **unaccepted local proposal**, `CreativeConceptBatchProposal` version `0.1.0`. It is not the C01 catalog, a shared contract, or an implemented public API. The module is deliberately not exported from `package.json` and is not wired into the current API or runtime.

The proposal consumes the existing validated `CreativeBrief` and `EventIntelligencePackage`, the current separate `AssetPermissionEvidence` shape, the existing C03 `MeteredAttemptRequest` and `ReservedAttempt` shapes, the current `DesignVersion` validator, the native image decoder, and content hash helper. Request references are asset IDs resolved only inside the validated package. Each one must have separate owner evidence bound to tenant, project, package, asset, content hash, the `reproduce` action, and an unexpired check. A request reference or role reference carries no permission. Role references remain opaque because no shared reference-role vocabulary has been accepted.

The batch proposal also requires an explicit host policy snapshot and an explicit adapter/configuration/prompt-template snapshot. The policy supplies its own concept/reference/elapsed/byte bounds and budget-snapshot expiry; this module chooses no tenant count or spend policy and does not reserve, estimate, settle, or release money. It validates the structure and binding of the current `MeteredAttemptRequest` and `ReservedAttempt` shapes as reported evidence only; that validation does not prove a trusted reservation, authorize dispatch, resolve a hold, or establish accepted Finance semantics. Actual per-concept work requires a separately returned C03 reservation and distinct billable, transport, and provider identities. The adapter snapshot names the native `/images/edits` route for a referenced initial concept, with no parent artwork. It does not choose a model, configuration, or prompt template. Its operation mapping is a proposal reference, not accepted C03 agreement.

The reducer checks the original request-reference keys before normalizing them, so creation and historical replay both use the same strict allowlist. The normalized policy snapshot retains the validated tenant, project, and brief IDs. Stored metering attempts are deeply readonly in the TypeScript output while the imported upstream request type remains unchanged and mutable.

Each ordered slot receives a stable scoped concept identity, a stable logical-operation identity, a `null` parent, and exact package/asset/role/permission lineage. The append-only reducer computes event hashes locally and also checks tenant, project, action, batch, slot, attempt, transport, and reservation identities. Exact event replay is idempotent; changed payload or context conflicts. Only a known failed slot can receive a new C03-shaped reservation, and every retry must have new billable, transport, and reservation identities. A completed slot cannot dispatch again.

Every attempt-related event requires non-empty billable and transport identities, validated against the exact attempt before replay or deduplication. A `cancel_concept` event may omit both identities only when that slot has never received an attempt; cancellation of an attempted slot binds its current billable and transport identities.

Published `DesignVersion` IDs are unique across slots in a batch. The same `artifact_id` may be referenced by more than one slot only when the content hash and media type match exactly; a conflicting artifact identity rejects before the batch changes. Exact replay of the original publication event remains a duplicate. Optional `logical_operation_id`, `billable_attempt_id`, `transport_attempt_id`, and `provider_request_id` fields on a `DesignVersion` are checked against the slot's staged attempt and its provider observation when supplied. Omitting those optional envelope fields remains compatible with the current version contract.

The adapter snapshot accepts the declared `MeteredOperationKind` values at construction, matching the output type. This local check does not define a provider-operation mapping; the snapshot's mapping reference remains a proposal until the owning contract is accepted.

Unknown outcomes retain their original provider and usage evidence. A later observation may reconcile that same attempt and continue staging without a new dispatch; the unknown financial exposure remains recorded until actual C03 evidence resolves it. Staged metadata can reconcile only for the same attempt and exact bytes hash. Cancellation suppresses publication permanently while allowing append-only late provider evidence for the exact attempt; that evidence keeps the unknown hold visible. These transitions are a pure in-memory model, not a durable store or proof that a host supplied authentic authority.

`inspectCreativeConceptImageBytes` snapshots the supplied read-only typed-array view before asynchronous decode, calls the existing native decoder, verifies the exact media type and optional expected dimensions, and hashes the same byte snapshot. The reducer can record a local `artifact_rejected` event for that exact response hash, preserving the successful provider and usage observation while keeping the slot failed and unpublished. Staging also checks the explicit adapter output format. `inspectCreativeConceptReferenceBytes` checks exact ordered asset identity, package hash, native dimensions, individual byte limits, aggregate byte limits, and the separate permission-evidence reference. The byte limits are explicit inputs from the host policy. Neither helper resolves references, calls a provider, stages bytes, or publishes a version.

## Five required outcomes

| Outcome | This source slice proves | Still required for CE04 acceptance |
| --- | --- | --- |
| Two authorized references and count two produce independent parentless candidates | Synthetic package/rights/policy fixtures, two stable ordered slots, distinct C03-shaped attempts, two exact hashes, complete local config/template/attempt/usage lineage, and no local visibility before the commit event | Actual public API request/response, trusted rights and count policy, native intercepted `/images/edits` call with exactly two authorized byte inputs, C03 and CE11 evidence, CE08 immutable same-connection publication, and visibility checks before and after commit |
| Zero/excess count, stale brief, revoked/cross-scope reference, expired permission or budget rejects | Source proposal rejects the listed structural/hash/expiry mutations before an attempt can be added | Current owner-backed brief, rights, job/lease, policy and budget checks at the real API and final send boundary, with actual C03 proof of zero billable work |
| Corrupt, empty, wrong-format or wrong-dimension bytes fail | The existing native image decoder and hash helper reject synthetic invalid bytes; a same-attempt rejection event retains provider/usage evidence without staging or publishing, and staged format must match the explicit configuration | Actual provider-attempt evidence and CE09/adapter inspection outcome, no version row or visible candidate, tested through the actual API and shared store |
| Crash after response/stage recovers the same bytes/hash/attempt | Pure event replay and same-attempt staged metadata reconciliation preserve the proposal’s attempt and hash | Hard process exit/reopen against real object storage and SQLite, same-connection CE08 prepare/commit/recovery, identical bytes/hash/attempt, and one actual generation dispatch |
| Duplicate, cancellation, late and lost responses preserve identity and conservative uncertainty | Scoped replay conflicts, unique attempt identities, no new dispatch for unknown/staged/completed/cancelled slots, same-attempt reconciliation, immutable cancellation and suppressed late publication are covered by pure reducer tests | Actual shared job cancellation/lease/current-context fence at each send, real C03 hold/settlement, CE11 outbox, duplicate API replay, late transport response and process-restart tests |

The tests use synthetic rights, budget, C03 reservation, provider response, storage-stage, and commit evidence. They exercise the checked-in native codec offline and do not call a live provider or establish real API, authorization, Finance, Neatlogs, inspection, SQLite recovery, or object-store behavior. The five original cases remain required and open.

## Required later integration

The accepted API currently accepts one generate action with one provider dispatch and one job result. The public API and job/result types must version the requested count, exact reference IDs and roles, ordered concept results, partial outcome state, progress/resume behavior, and independent lineage. The job path must keep exact duplicate action replay distinct from a fresh action, and must avoid regeneration of completed slots.

The API/runtime integration must obtain current brief, ResearchPackage, rights, reference bytes, and tenant count/elapsed/spend policy from owner ports. It must not accept request flags, evidence references, or host snapshots as proof. After every authority await, including the final authorization await, it must synchronously re-check the live durable job status, lease/token, brief/context, permission, deadline and cancellation state immediately before the transport send. Actual cancellation and lease expiry need zero-send regression coverage.

The current OpenAI adapter sends unreferenced generation through `/images/generations`; its reference manifest is edit-only and requires a real parent DesignVersion. A versioned adapter capability must support an initial logical concept with authorized exact reference bytes through documented `/images/edits`, retain `parent_version_id: null`, enforce native byte/hash/MIME/dimension/aggregate limits, and define the accepted C03 operation-kind and retry mapping. It must not synthesize a parent from a reference, add a made-up `image[]` generation field, or fetch arbitrary URLs. The offline intercepted transport must assert that exactly the authorized bytes and scope are sent, with no SDK retry.

CE03 remains the sole reservation/attempt executor and Finance remains the ledger owner. CE11 must keep logical operation, billable attempt, transport attempt, provider request, usage observation, unknown outcome and outbox identities linked per concept. Unknown usage and cancelled-after-send holds must never be released based only on job lease expiry or a caller flag.

CE09 must provide actual review-only inspection evidence and deterministic invalid-artifact handling. CE08 must extend its current immutable-byte/metadata commit and recovery path for multiple ordered candidates, preserve partial results, and make bytes and required lineage durable before any candidate becomes visible. No provider, observer, or external callback may run inside a borrowed SQLite transaction. Private and public projections must add the accepted configuration, prompt-template, reference, attempt, usage and per-concept unknown lineage without exposing secrets or source credentials.

The integration change needs actual public consumers, package/build exports, migrations where needed, `make check TARGET=concepts MODE=mock`, both pinned Node runtimes, strict TypeScript consumers, process-crash/reopen tests, and all five end-to-end cases. Live GPT Image generation/editing, Finance agreement, Neatlogs acknowledgement, model promotion, and external account/host acceptance remain separately gated.
