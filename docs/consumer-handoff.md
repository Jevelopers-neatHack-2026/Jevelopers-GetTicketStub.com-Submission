Pre-provision exact clean checkouts and locked dependencies. A private paths JSON may map a repository to a checkout string, or to `{ "checkout": "...", "shared": "...", "acknowledgement": "..." }`. The additional paths locate an exact clean shared source checkout or actual locked archive, and the independently reviewed acknowledgement JSON. Only local locations are overridden; source/schema/artifact/fixture/acknowledgement claims remain checked-in pins.

```sh
export npm_config_offline=true npm_config_audit=false npm_config_fund=false
npm ci
npm run contracts:consumers -- --paths /absolute/private/consumer-paths.json
```

A reviewed consumer row must supply its clean source_sha, offline dependency_mode, exact command `["node", "relative/contract-driver.mjs"]`, complete schema_pins with contract/version/schema_id/sha256, fixture_digest, package_content_digest and shared_source_revision. Source mode uses `shared_binding: { "mode": "source", "local_path": null }` plus a provisioned path: actual Git HEAD must match the pin and the entire checkout must be clean. Artifact mode uses `{ "mode": "artifact", "local_path": null }` plus a provisioned archive whose actual SHA512 SRI equals package_integrity. The archive parser rejects links, traversal, duplicates, malformed headers and oversized entries.

Both modes compare the entire package content set/digest against the canonical candidate, including helper code, generated bindings, validator bytes, export map, schemas, fixtures, docs and third-party notices. A SHA-shaped string or unchanged schema hashes cannot certify changed helper code. The self-excluded package manifest is separately validated against the expected digest/file list. The runner first executes every required version's canonical fixtures in a short-lived verifier process it controls, before consumer code starts, and stores minimized verification separately from driver declarations. The verifier exits after that run so repeated snapshots do not accumulate in the runner's module cache.

The consumer driver then runs in a separate process. Module hooks only resolve imports to the verified snapshot and check loaded bytes; they emit no audit file. The parent connects to the child's native V8 debugger on an ephemeral localhost-only endpoint before driver code runs, verifies actual parsed module source, and observes the trusted fixture function's result at its return breakpoint. The parent compares the actual manifest with its independently retained fixture and stores minimized coverage in parent memory. Writing a fake audit file, echoing metadata or merely importing the helper cannot create this evidence. Every required contract/version needs actual positive/negative and applicable semantic fixture execution. Debugger eval scripts are distinct from module imports, and real paths are normalized before comparison.

The trusted probe must report status passed and one unique, nonempty case-count record for every required contract/version. Malformed JSON, missing records, incomplete coverage or a non-passed result fails as TRUSTED_PROBE_INVALID_RESULT before consumer execution. ENOBUFS is TRUSTED_PROBE_OUTPUT_LIMIT; startup failures remain TRUSTED_PROBE_UNAVAILABLE. Unexpected observer processing exceptions use INSPECTOR_PROCESSING_FAILED instead of exception messages. These runner diagnostics provide no execution credit or artifact blame.

This uses Node's [module hooks](https://nodejs.org/api/module.html#moduleregisterhooksoptions) and [native inspector](https://nodejs.org/api/inspector.html). Local debugger transport is verification plumbing, not an external provider call. The driver still owns its genuine downstream adapter scenarios; package-owned fixture execution is not domain adoption.

Observation has a 60-second deadline. Deadline, startup, socket and child-exit failures settle all outstanding observation waits with a named failure; queued commands cannot revive a closed session. Before normal disconnect, a protocol round trip fences the current event queue, and final output is collected through child close. Failure cleanup closes the socket, force-terminates an active driver and bounds the reaping wait to one second. A transport failure or timeout supplies no execution evidence. [SC-CI-001](../compatibility/ci-findings.json) records the original cancellation and pending independent verification.

The acknowledgement must be status=accepted with consumer_sha, shared_source_revision, package_content_digest, fixture_digest, schema_pins_digest, command_digest, package_integrity (null for source mode), reviewer, reviewed_at and GitHub record_ref. Its separately supplied actual JSON must match those fields. This establishes machine consistency and review provenance pointers; the repository owners must authenticate and accept the review. A synthetic record in tests is labelled synthetic and cannot fill a real manifest row.

The driver reads public binding metadata from SHARED_CONTRACTS_BINDING_CONFIG, imports the canonical package helper, executes every required_fixtures contract/version and its reviewed local domain cases, and emits one JSON receipt containing status=passed, consumer_sha, shared_source_revision, fixture_digest, package_content_digest, package_integrity, binding_nonce and the exact contracts_tested list. The readable nonce correlates the declaration with this invocation; it is not a secret or execution proof. Trusted verification and native parent observations remain separate from that declaration. Scope-sensitive cases use an independent server/fixture context, never payload fields as expected authority.

Only a minimal environment is passed; no provider credentials. The reviewed driver cannot import network-capable modules, worker/child processes or use global fetch through the provided hook. Hooks, debugger observation and JavaScript execution are not a hostile-code sandbox. Consumer code and acknowledgement authenticity still require actual owner review; these checks establish package fixture contribution and observed imports/calls, not authenticated business behavior. Missing/dirty/wrong checkout, missing pin/command/record, forged/inconsistent receipt, incomplete role/schema coverage, changed package/schema/fixture bytes or driver failures are named BLOCKED/failed results with no skipped pass.

The [whole-catalog installed example](../examples/fixture-consumer.mjs) illustrates import/copy fixture consumption. To copy fixtures, retain their exact manifest/digest and expected policy/code/path, then run them through the pinned imported helper. Do not copy generated business policy or create a second schema writer.

Migration requires producer/consumer agreement on each boundary. Creative's local envelope uses a string producer and string source references; canonical producer metadata and typed opaque references need explicit mappings. Local 1.0/1.1 names do not imply canonical semver support. Legacy IDs need reviewed identity mapping rather than invented UUIDs. ResearchPackage/EIP naming and closed/additive handling remain proposals. JEV Score string versus array criteria/legend uses the existing explicit adapters and pending owner decision; numeric local probabilities/amounts require exact canonical primitive handling. ApprovalVerificationOutcome and receipt/consumption proposals must retain distinct request, authority and delivery meanings.

Upgrade by recording source SHA, package version/integrity/content digest, each schema identity/hash, fixture digest and the tested consumer SHA together; execute the exact recorded offline driver and review its result. Keep the old immutable pin and encoding for rollback. A failing consumer blocks promotion. Rollback restores the prior exact reviewed pin, without rewriting historical observations. Deprecated removals need notice/replacement, at least 90 days, all named acknowledgements and passing migration fixtures. No prior accepted major is invented.
