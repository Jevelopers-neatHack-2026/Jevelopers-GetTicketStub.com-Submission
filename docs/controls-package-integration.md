# Controls package integration

`creative-engine/controls` is a public package subpath for the controls runtime, its declarations, and the inspection-consumer helpers. The same package also exposes `creative-engine/inspection` with its CE-09 runtime and declarations. The root package allowlists both runtime trees and their dependencies, with exact model runtime files plus the codec runtime manifest and lock, so `npm pack` includes implementation and every public self-import target while leaving tests, fixtures, examples, execution evidence, developer scripts, and installed native codec dependencies out of the tarball.

`make build` checks every controls and inspection runtime module, the existing package-export runtime prerequisite, and both strict type consumers. `make check TARGET=controls MODE=mock` runs the existing controls fixtures, source typecheck, and a real `npm pack` installation check. That check installs the candidate tarball into a fresh offline consumer, imports all 13 current public package subpaths, exercises durable SQLite replay and zero-call counters through `creative-engine/controls`, and typechecks installed controls and inspection consumers in strict NodeNext/ES2022 mode with TypeScript 5.9.3. Positive and expected-negative assertions resolve through the installed package declarations without a repository source alias.

The controls workflow runs on Node 22.23.3 and 24.15.0. It caches and installs the root, example, and locked `src/models/codec-runtime` dependency sets before the full build, aggregate offline checks, and existing Chromium plus axe roundtrip. Codec install scripts remain disabled. The existing native controls tests decode fixture PNG, JPEG, and WebP bytes with the installed codec; the installed controls consumer verifies its package boundary and SQLite behavior without loading the codec.

This package gate verifies a locally packed tarball and consumer compatibility. It does not publish a registry package or close external producer, application, host, or release acceptance.
