# Private asset source discovery

The private `discoverAssetCandidates` path accepts completed HTML, XHTML, or JSON-LD response bytes and invokes the existing deterministic parser inside `EvidenceStore`. It accepts only a document whose retrieval metadata reports zero redirects; pages with redirects are rejected. It persists bounded, exact source excerpts and source-structure metadata in the tenant-private SQLite evidence store, then returns current-authorized candidate descriptors backed by reopened ciphertext. It does not fetch an image, script, font, CSS resource, canonical URL, or remote identifier. The zero-redirect check validates the supplied retrieval metadata; this private API does not itself prove that the bytes came from the controlled retrieval boundary.

The descriptor reports what the source said. Page-level Open Graph images, `<img src>`, and icon links have an `unassigned-page` association. JSON-LD image and logo values retain the existing event or organization pointer; a nested organizer value is recorded as an unverified organizer source claim. Empty or missing HTML/XHTML URL attributes are quarantined as `invalid_or_empty`; their private excerpt is the exact nonempty attribute token (for example, `src=""` or `src`) and its `excerptKind` is `html-empty-attribute-token`. Other claims use their exact source value bytes with `excerptKind: url-value`. The token excerpt describes an empty or missing source attribute, never an asset URL. These associations do not establish an event occurrence, company identity, ownership, role, rights, permission, MIME type, dimensions, licensing, palette, or font. Candidate roles and permissions remain `unknown`; inspection remains `pending`.

Supported forms are Open Graph `og:image` properties; HTML/XHTML `<img src>` and `icon`, `shortcut icon`, `apple-touch-icon`, or `mask-icon` links; and recognized event or organization JSON-LD `image`/`logo` string values, string arrays, and URL-like scalar fields on image objects. JSON-LD locations are classified from the parser's RFC 6901 pointers, not from the flattened display field. The pointer and exact UTF-8 source range remain private provenance. Unsupported forms include CSS backgrounds, `srcset`, dynamic/browser-generated resources, and font assets. A candidate count or parser limit is all-or-error and does not publish a successful-looking prefix.

Relative and protocol-relative asset suggestions resolve against the completed response URL. `<base>` and canonical tags do not override that URL. A safe HTTP(S) suggestion may retain its source fragment as private metadata while its separate fetch suggestion omits the fragment. Unsupported schemes, credential-bearing URLs, private or numeric hosts, sensitive-query names, malformed values, and overlong values receive fixed quarantine reasons. The source response URL itself is checked with the existing URL policy and sensitive-query filter; failures return a fixed code without echoing the URL. This descriptor check does not prove that an arbitrary `RetrievedDocument` came from a completed safe retrieval, and it is not a substitute for the separate controlled-retrieval integration.

The asset representation uses manifest and encrypted bundle version 3. Its family identity is domain-separated from raw source composition and keyed by the actual normalized response URL and `external` source kind. Full source bytes are hashed inside the store; unchanged bytes and selector/extractor inputs replay the same immutable record, while changed bytes or derivation inputs append a family version. Asset excerpts have their own byte digests, exact original ranges, ordered candidate metadata, and a derivation digest. Those excerpt digests do not describe unfetched asset bytes. Existing raw v1 and PDF-derived v2 bundles remain readable without rewriting their sealed payloads; manifest schema remains monotonic when v3 records and later PDF/raw writes coexist.

The current writable asset derivation profile is selector `ei-asset-source-selector/6` with extractor `ei-deterministic-extraction/1.6.0`. It preserves complete original HTML attribute-value ranges using ASCII HTML whitespace syntax and XHTML source locations using XML syntax whitespace (TAB, LF, CR, and SPACE), and represents genuinely empty/missing HTML attributes with an exact validated attribute-token excerpt while keeping the candidate URL empty and quarantined. In XHTML, XML attribute names remain case-sensitive for source binding: extraction prefers the exact standardized lowercase name when present, and uses the first case-insensitive spelling only as a compatibility fallback when the lowercase name is absent. This keeps uppercase-only legacy claims supported while binding the selected decoded value, URL policy, source range, and excerpt to one exact name; when both `src` and `SRC` occur, `src` wins regardless of order. HTML continues to use parse5's existing duplicate-attribute recovery behavior. Selector 1, 2, and 3 remain explicitly pinned read profiles at their original `ei-deterministic-extraction/1.3.0` version; selector 3 carries the empty-token excerpt semantics introduced in that profile. Selector 4 remains pinned at `ei-deterministic-extraction/1.4.0`, and selector 5 at `ei-deterministic-extraction/1.5.0`. The store keeps an explicit profile allowlist for immutable records. A selector or extractor bump must add the new writer pair and retain each historical pair that remains readable, with its original validation rules; an unknown profile fails closed. Existing records are never reparsed or relabeled during a bump.

Fixed asset-producer ceilings are 2 MiB per document, 64 candidates, 8 KiB per excerpt, 64 KiB total excerpt bytes, 64 KiB candidate metadata, and a 2.5 second parser deadline. Existing store position, provenance, encrypted bundle, selected-materialization, tenant ACL, key, expiry, cancellation, and retention limits remain in force. Bytes are copied before parser awaits, each excerpt is checked against the original response range, and persistence is an atomic SQLite compare-and-swap. A reopen/readback validates the ciphertext, source hash, excerpt digests, locators, candidate ordering, selector version, empty-token syntax where applicable, and current authorization before descriptors are returned.

This is a private source-evidence component only. Safe-fetch proof, browser rendering, image-byte inspection/decoding, SVG sanitization, permission selection, public asset routes, canonical company evidence, and product/API/UI integration remain separate work and acceptance requirements.
