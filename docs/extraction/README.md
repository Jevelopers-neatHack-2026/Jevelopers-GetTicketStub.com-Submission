# Deterministic extraction (internal)

`extractDeterministically` parses a completed `RetrievedDocument` in memory. It performs no retrieval, DNS lookup, subresource request, external entity resolution, JavaScript execution, provider call, or canonical-record write. A canonical URL or JSON-LD `@id` stays a suggestion and is never fetched.

The parser accepts UTF-8 `text/html`, `application/xhtml+xml`, `text/plain`, and standalone `application/ld+json`. Other media types and declared non-UTF-8 encodings return an explicit unsupported status. Malformed UTF-8 is rejected rather than guessed. HTML uses the pinned [parse5 8.0.1 parser](https://parse5.js.org/interfaces/parse5.ParserOptions.html) through [parse5-parser-stream 8.0.0](https://parse5.js.org/modules/parse5-parser-stream.html), with scripting disabled and no script callbacks. XHTML uses pinned [sax 1.6.1](https://github.com/isaacs/sax-js) in strict XML mode with source offsets; it accepts the five predefined XML entities and numeric character references, ignores external identifiers, and rejects internal DTD/entity declarations without resolving them. Embedded XHTML JSON-LD is parsed from the ordered XML character data, including decoded references and CDATA, with a logical-offset map back to original source bytes. HTML charset declarations are read from parsed `<meta charset>` or valid `http-equiv="content-type"` elements; a transport header charset takes precedence. XML declarations are checked for XHTML. JSON-LD uses the Node runtime's JSON parser plus a bounded source-position indexer; the result records the exact Node patch version used for parsing.

Every candidate locator is a half-open UTF-8 byte range into the complete original response bytes. Its `rawValue` is exactly that source slice; `normalizedValue` carries decoded HTML entities or parsed JSON scalar values with whitespace normalization. An embedded JSON-LD candidate also includes an RFC 6901 pointer within its script block; the byte range remains the locator against the complete HTML response. Entity occurrences are identified by source block and pointer, so multiple events and editions remain separate even when their `@id` strings match. Remote `@context`, `@id`, canonical, and Open Graph URL values are not dereferenced.

For XHTML, attribute names are XML case-sensitive and their original spelling remains attached to each parsed attribute for source-range selection. The deterministic extractor prefers an exact standardized lowercase name such as `src`, `href`, `content`, `rel`, `property`, or `type`; if absent, it selects the first case-insensitive spelling as a compatibility fallback, preserving uppercase-only inputs. If both `src` and `SRC` exist, the exact lowercase `src` attribute is selected regardless of source order, and its decoded value, URL policy input, and UTF-8 locator stay bound together. HTML keeps parse5's existing first-duplicate behavior.

`assetSources` carries bounded static URL claims from Open Graph image metadata, HTML/XHTML image and icon attributes, and recognized event/organization JSON-LD image or logo values. Page-level values remain unassigned; JSON-LD values retain exact entity or nested organizer source pointers. These associations are unverified claims and grant no role, identity, rights, or permission. The parser does not resolve asset URLs beyond its source-only suggestion field and never requests asset bytes. The durable private store applies its own URL checks and excerpt bounds before issuing authorized descriptors; see [private asset source discovery](../brand-research/asset-source-discovery.md).

The parser's attribute candidate locator continues to describe the URL value bytes, including a zero-length range for an empty or missing HTML/XHTML attribute value. The private store handles those claims with a separate parser-produced, exact nonempty attribute-token excerpt and a fixed `invalid_or_empty` quarantine; it does not turn the token into a URL or loosen the positive-length stored-position rule.

Static visible text excludes `head`, `script`, `style`, `template`, `noscript`, `title`, and elements marked hidden, inert, `aria-hidden`, or by recognized inline visibility styles. Visible cancellation, reschedule, and access phrases are matched across adjacent inline descendants within a bounded visible block; their byte ranges point to the exact original source span, including markup between the text fragments. These signals remain separately retained after the general visible-text budget is reached, subject to the document and signal-candidate ceilings. Conflicting values and page-level metadata that cannot safely be assigned across multiple event nodes remain explicit in the result. These are source candidates, not verified facts.

Statuses include `PARTIAL`, `NO_ANSWER`, `JS_REQUIRED`, `ACCESS_RESTRICTED`, `UNSUPPORTED_MEDIA`, `UNSUPPORTED_ENCODING`, `MALFORMED_ENCODING`, `RESOURCE_LIMIT`, `CANCELED`, and `INVALID_INPUT`. When a resource ceiling is reached after some evidence was retained, status may remain `PARTIAL` and `termination` records `RESOURCE_LIMIT`; a total quota failure returns `RESOURCE_LIMIT`. JSON-LD blocks stopped by a quota are labeled `resource_limited`, while malformed source is labeled `malformed`. A script tag alone does not imply `JS_REQUIRED`: that status requires explicit noscript copy or a sparse recognized application mount point with script elements. Access and JavaScript signals are conservative heuristics, not a browser rendering result.

Default ceilings bound response bytes (2 MiB), HTML nodes (100,000), HTML parser time (2.5 seconds), visible text (4,000 segments / 512 KiB), status/access phrases (128 each), canonical links (256), page metadata values (1,000), asset source claims (128), JSON-LD blocks (32), JSON-LD bytes per block (512 KiB), JSON nesting (64), JSON nodes per block (30,000), entities (128), candidates per entity (256), diagnostics (128), and noscript traversal/signals. Callers may lower limits. Parser recovery errors and truncated evidence are reported diagnostically. Visible status and access phrases have their own bounded retention, so a cancellation notice later in the document can remain even after the general visible-text budget is consumed.

The pinned XHTML SAX parser has a separate 64 Ki code-unit threshold for token buffers that it cannot flush, including comments, attribute values, processing-instruction bodies, and entity names. Text and CDATA buffers are flushed during parsing. SAX checks buffer lengths at input-chunk boundaries, so an unflushable token can cross the threshold within a chunk before the parser stops; this returns `XHTML_TOKEN_BUFFER_LIMIT` with `RESOURCE_LIMIT` termination. The default XHTML chunk size is 16 Ki code units.

This is an internal partial extraction component for controlled retrieval. It does not define or implement the accepted canonical event schema, full research API, external release, or persistence behavior.
