# Actual saved-artwork inspection consumer

This consumer connects a completed native Apply to the public CE09 `inspect` operation on the qualified inspection base `18b5e6076f6275af763bdd45bf77c6a644a8bddc`. It is local implementation evidence, not acceptance. All 18 required leaves remain open. The original CE05 and CE09 requirements and global owner roles remain unchanged.

`InspectionControlsAdapter` is exported from `creative-engine/controls`. It accepts a trusted application principal, an existing `CreativeControlsAdapter`, and the same CreativeRuntimePorts. `start` accepts only `source_operation_id` and a distinct stable `inspection_action_id`. The source must resolve to an exact completed backend job and immutable DesignVersion. The adapter derives tenant, project, actor, current brief, design and artifact hashes from trusted state. It rejects borrowed controls transactions, foreign identities, changed request identities and stale fresh selections. It never accepts reports, recommendations, repair budgets or provider configuration from browser input.

One creative SQLite connection owns backend jobs, immutable versions, artifact bytes, inspection sessions, observer/decision stages and CE11 outbox records. The separate controls database stores only stable request bytes/hashes and their saved-selection binding. Lookup uses public `job.status`; completed inspection replay uses public `inspect` to validate the durable report. Resolving Apply/repair sources uses read-only jobs/storage ports. An incomplete repair source cannot start repair work. Concurrent duplicate requests share one in-process promise and the backend's durable action identity. Interrupted dispatch remains unresolved with the same identity; it is never regenerated by the UI.

`currentSource` recovers the exact currently selected saved Apply or completed repair through its actor-scoped durable binding, public job and immutable version. It rereads current selection/brief authority after awaits and returns only a safe operation/version/artifact identity. Page reload before the first inspection therefore restores the saved preview and permits a separate explicit inspection without repeating Apply or dispatching any work during lookup. Delayed startup responses obey the same generation and artifact guards as active inspection results.

The example supplies explicitly labeled offline native transport, observer, DecisionPort, Finance and current rights doubles. Actual producer code decodes PNG, JPEG and WebP, checks the saved artifact, emits independent Noul/Score questions followed by dependent Choice, meters each stage, and persists the report. Observer/JEV doubles return observations/answers, never successful reports. JEV receives bounded structured text; it receives no raw image. The fixture counts invocations separately from mock sends, which increment only after the public transport acknowledgement/final authorization callback resolves.

The browser renders a bounded immutable projection: safe operation/version/artifact references, the report hash, request/decision hashes, fixed status/outcome messages and fixed backend limit fields. It drops nested extra fields and private prose. Completion means the inspection job/report completed; refusal and human-review reports remain visibly distinct from favorable review. Failed jobs have no report hash or favorable outcome. Pending, unavailable, failed, cancelled and unknown outcomes retain the saved artwork. Usage completeness is separate from total cost and reservation status; the latter remain unknown in this projection. Missing/partial raw usage retains Finance holds. Complete raw usage with unknown owner mapping is tested separately: it can settle under C03 while inspection usage remains unknown and repair stays unavailable.

Inspection never approves artwork, certifies legal/print suitability, authorizes purchase or automatically repairs. The explicit repair action is `image.edit`, independently authorized through the public API and bound to the exact inspection report hash. Its instruction preserves current style preferences, verified facts, approved assets and locked fields. There is no fallback style selection. The backend owns the original immutable ancestry root and cumulative limits of two repairs, 60 seconds and three fixture units. New action IDs, descendants and process reopen do not reset them. A repair creates a new immutable saved child, which must be inspected separately. Lost responses retry the same repair action. Read-only page recovery restores completed children and exposes an existing pending repair identity for recovery.

Remaining fixture units preserve the backend's finite fractional value within `[0,3]`; a half-unit repair leaves exactly 2.5 units in the next report and browser view. Repair counts and elapsed milliseconds remain bounded integers. The projection performs no rounding or alternative budget accounting.

Displayed version/hash and request-generation checks prevent delayed inspection, lookup, error or startup responses from replacing newer Apply/Restore/repair state. Repair success clears old inspection references and updates preview/artifact text coherently. Keyboard Enter, focused statuses/alerts, native labels and axe checks cover the real Chromium journey. Synthetic malformed-response interception is used only for negative tests.
