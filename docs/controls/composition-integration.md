All application provider, JEV, vision, issuer, Finance and production calls are zero. Artwork style exercises the genuine local artwork edit producer with intercepted native transport and simulated reservations; its fixture counters distinguish those edits from composition changes. ## Version and authority boundaries

The existing `creative-controls/1.0` and `/1.1`, `creative-apply/1.0` and `/1.1`, public package inventory and limits stay closed. Composition uses `CreativeCompositionControlPolicy/1.0`, `creative-composition-controls/1.0`, `creative-composition-apply/1.0`, and separately reviewed `creative-composition-initialize/1.0` and `creative-composition-renew/1.0` actions. Unknown versions, extra fields, executable values, accessors, ambiguous policy mappings and overlapping geometry proposals fail closed.

The authenticated host supplies category meanings, target layer/asset identities, units, ranges, policy time and locks. There are no category-to-geometry defaults in the library. The projection is derived after the neutral immutable revision hash. Its own digest binds the exact scope, full revision/state, design/artwork, selection, edit policy, control policy and preview. The projection is not embedded in neutral hash material and does not introduce a hash fixed point. A read-only current result, favorable inspection or selected version never grants approval or purchase.

`fixtures/controls/composition-policy.mjs` declares the fixture's small/medium/large (18/24/36 pt), centered/stacked geometry, q01 balanced/name alternatives, and approved-logo top/bottom geometry. Layout and q01 use one joint mapping, so their order cannot overwrite a prior operation. Exact values outside that mapping display an unrepresented categorical value rather than a guessed baseline. Both categorical and exact operations pass the actual C04 plan validator and neutral locks, factual restrictions and rights checks. Distinct text, size and geometry changes can combine into one immutable child; incompatible writes reject before execution.

## Exact read-only draft review

`CompositionControlsAdapter.review(principal, { projection_sha256, draft })` normalizes the draft using the current public composition GET, the actual stored revision and the trusted server policy. The loopback `POST /api/composition/review` exposes its closed `CreativeCompositionDraftReview/1.0` presentation: exact operation kind, layer, approved asset identity where applicable, actual before and after text, decimal-string size/unit or normalized geometry, and projection/draft/review hashes. It creates no job, journal row, preview or revision and performs no image/JEV/vision/reservation operation. The draft review revalidates stored revision/state/preview bytes and finishes with a second genuine public GET, including native owner and synchronous store fences. Its two owner reads/assertions are counted separately from mutation effects.

The browser verifies the closed response against its loaded projection, exact before values, target/asset membership, requested draft, bounds and digest before enabling Apply. A changed draft, refreshed scope or newly submitted artwork action invalidates the pending review response, including its error, cleanup and focus paths. The review displays unspecified geometry explicitly; it does not infer missing sizes or layout. Categorical after values come from the server policy's existing exact plan mapping. Apply retains the closed `creative-composition-apply/1.0` payload and independently rebuilds the same plan against current authority, so an old review cannot execute against a new composition. Review neither produces a preview of the proposed state nor grants approval or purchase.

## Durable reviewed Apply and preview reads

The artwork style recovery path and its scoped durable nonadmission journal are
specified separately in [Reviewed artwork action recovery](artwork-recovery.md).
The browser consumes that closed result before unlocking a fresh style or
composition review after a rejected, completed, failed or cancelled style action.

The adapter owns `control_composition_actions_v1` and the scoped `control_composition_rejections_v1` journal on the existing controls SQLite connection. It stores the normalized scoped reviewed action and exact request/hash before invoke, and binds the genuine backend job. Caller-owned BEGIN or SAVEPOINT transactions reject before host callbacks or writes. It owns no selection pointer, rights authority, approval issuer or renderer.

Read/refresh never initialize. Missing composition shows the exact selected artwork binding; initialization requires an explicit review and separate Apply. The four exact operations are text, text size, layer layout and approved-logo position. Each goes through public create/get/update, the real durable action and job, exact parent/target/full hashes and owner preview bytes. Pure composition preserves original artwork bytes and the DesignVersion/selection identities.

Retry uses the original durable request. Read-existing recovery only observes the real stored job/action; it makes no executor or preview call and does not write an acknowledgement. A completed response is historical until a separate fail-closed current GET proves currentness. Pending/unknown response loss keeps the original action identity and gates new controls mutations until reconciliation. Reload may read the existing genuine durable status; that read executes no producer, preview or paid work. It never retries automatically. The browser stores only opaque scoped action identity, not the personalization draft. Changed action bytes under an existing ID conflict. Publication and cancellation remain backend authoritative.

Artwork and composition previews are separate. The same-origin composition endpoint validates scope, current revision/full hash/preview hash and rechecks context after the asynchronous result. The browser bounds reads to 25 MiB, verifies exact byte length/hash/MIME, waits for real image load/decode and checks dimensions. No URL, access locator, provider request identity or raw preview access enters the browser projection. Generation, action identity and terminal guards cover asynchronous success, errors and cleanup. Unknown status cannot overwrite an observed terminal completion.

## History and explicit renewal

The additive API 1.3 consumer reads scoped, deterministic, paginated identity-only history. Equal-time rows retain the producer’s binary ID order; the consumer validates that order without locale comparison or sorting untrusted rows. Full-page and concatenated single-row histories are exercised through the genuine public producer, alongside duplicate, reversed-order and cross-scope rejection. It exposes current full revision identity, parent pairs, times and selection compatibility; it grants no preview/access, approval or purchase. A separate renewal review binds the exact expected current ID/full hash and current brief/design/artwork/selection. Explicit Apply persists that review and invokes `composition.revalidate` with a distinct candidate ID. The actual backend obtains fresh trusted evidence and enforces CAS/final fences before appending a child. The MOCK owner fixture reads the actual current package and policy while preserving locks and factual restrictions.

Expired proofs and public same-design Restore/ABA keep GET stale. History does not silently rebase, refresh or renew. Successful explicit renewal preserves old artwork/layers/geometry and historical hashes, displays a newly verified current preview, discards old drafts and requires a separate fresh controls Apply. Lost-response/reload recovery reconciles the same durable child without duplicate owner/preview execution. Pending cancellation remains cancelled and publishes no child; a preview owner call already in flight may finish once after release. Cancellation does not claim to abort renderer transport.

## Reproduce and evidence limits

Use pinned Node 22.23.3 and 24.15.0. Install only the two independently locked dependency directories (`examples/frontend-action-roundtrip` and `src/models/codec-runtime`), with codec scripts disabled. Run the existing build/source/type/package checks plus:

```sh
node --test tests/controls/composition-integration.test.mjs tests/controls/composition-view.test.mjs
node examples/frontend-action-roundtrip/node_modules/typescript/bin/tsc -p tests/controls/types/tsconfig.json
node fixtures/controls/installed-composition-check.mjs --evidence-dir build/controls-package-evidence/composition
cd examples/frontend-action-roundtrip
node node_modules/@playwright/test/cli.js test tests/composition.spec.mjs --project=actual-api
```

The installed consumer packs and installs the candidate into an independent offline directory, resolves the public package without source aliases, typechecks closed positive/negative consumers, and exercises genuine producer/store/preview lifecycles. Reopen tests gracefully close the host and start a fresh process. They do not claim abrupt-exit or crash durability; separate backend crash/publication proof is required.

The evidence preserves the original public pending-update cancellation failure on 7c and subsequent UI test failures. The merged main source at `e152e97fefb1a0293ffee989d573fe7c6b78d054` has paired post-merge local build, type, controls, artwork-recovery and installed-consumer results on Node 22.23.3 and 24.15.0, as detailed in [the verification receipt](https://github.com/Jevelopers-neatHack-2026/creative-engine/pull/57#issuecomment-6130377635). The earlier hosted jobs and 139-case browser runs remain tied to their tested candidate checkout; newer actual-main hosted runs are collected separately. The aggregate acceptance command remains blocked by owner evidence, and production-host durability, live external qualification, full gate #12 and cross-repository acceptance remain open. Retained execution evidence records exact source manifests, argv/runtime, raw logs and earlier failures.

For exact browser store custody, set `CONTROLS_BROWSER_EVIDENCE_DIR` to a new directory when running Playwright. The automatic actual-API test fixture finalizes the MOCK host after each case, copies its closed SQLite/object state and counters, and hashes every copied file. It does not depend on web-server signal teardown to preserve the last case. These captures prove orderly fixture state, not crash consistency. `x-mock-controls-principal` admits only declared alternate tenant/actor fixture negatives; it is not an application authentication interface. Browser gates bind observed status to the exact new action/result/current revision, and retain late response, preview and history negatives without focus theft or terminal downgrade.

Read-only recovery of a completed durable job requires current scoped view permission, even when edit permission has since been revoked and the adapter never received the completion response. It validates the genuine stored job/result/preview and returns a historical result without invoking an executor or caching acknowledgement. Revoked view permission and changed actor/tenant/project reject recovery. Pure text-size, layout and approved-logo geometry changes retain the legacy layer hash but change full revision/state and exact preview commitments; old external approval must still be treated as stale.

Valid-action failures always include their action identity and explicit `approval:false`/`purchase:false`. Their local controls `recovery` field distinguishes operation evidence from rejection of one request: `unknown` does not resolve the original operation, `terminal` requires the exact paired durable job to be failed/cancelled, and `not_admitted` requires a scoped, actor-bound negative-admission journal. Ordinary failed/stale responses, including a rejected duplicate over an existing pending row, cannot unlock another Apply.

The negative-admission journal stores only the action hash and closed failure receipt, never a name/draft or backend execution. Its conditional insert excludes admitted actions; the matching conditional action insert excludes rejected identities across SQLite connections. A rejected identity cannot later admit work, including an already awaiting request that resumes after rejection. Fresh authority requires a newly reviewed action with a new identity. Read-only lookup/retry of that identity returns the hash-checked rejection under current scoped view authority; it creates no job, preview, revision or current-pointer change.

The browser continues to cache only scoped opaque action identity/version. After reload it obtains the outcome from the actual server, including negative admission; no cached UI terminal flag or null lookup is authority. Missing, malformed, inaccessible and pending outcomes retain uncertainty. Explicit renewal and a fresh reviewed Apply become available after a confirmed stale rejection, while lost response and pending-operation recovery keep the same identity and cannot duplicate work. These checks use actual local API/SQLite with declared MOCK membership, rights and preview producer, not live issuer/provider or production output qualification.
