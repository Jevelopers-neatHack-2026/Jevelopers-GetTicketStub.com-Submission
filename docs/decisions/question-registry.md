# EI-owned JEV question registry

This module owns the EI question wording, typed TypeSafe question objects, label sets, and local immutable preparation plans for the seven JEV questions in issues [#16](https://github.com/Jevelopers-neatHack-2026/event-intelligence/issues/16), [#17](https://github.com/Jevelopers-neatHack-2026/event-intelligence/issues/17), and [#18](https://github.com/Jevelopers-neatHack-2026/event-intelligence/issues/18). The owner is **Agent and research**. This is a scoped contribution to source evidence, untrusted content, and asset work; it does not satisfy the shared acceptance roles for AGT-01, AGT-04, AGT-05, ART-05, FIN-01, or EVAL-02.

## Version and authority

The definitions keep the mandated question IDs ending in `:v1`. The EI-owned registry artifact is `2.0.0-draft.1`, with question schema `1.0.0` and rubric `1.0.0`. It does not reuse the promotion policy's configured question-registry pin `1.0.0`: the policy and corpus use older labels whose meanings do not match these questions. A canonical JSON SHA-256 `definitionHash` is recorded per question, and `QUESTION_REGISTRY_HASH` covers the registry version, schema version, policy identity/version, and definition hashes. Each definition also records the SHA-256 of the exact current policy, label file, and corpus manifest bytes it references.

The checked-in policy is `jev-ei-promotion` version `1.0.0`, status `proposed_unapproved`; its numeric thresholds are copied unchanged into each definition from the policy's `required_questions[].candidate_thresholds`. These values remain proposed and are blocked from use until owners reconcile labels, metrics, denominators, and corpus and publish an aligned policy pin. The registry records the current policy classes, metric definitions, denominators, sample minima, confidence-interval method, and an explicit reconciliation for every question. It does not authenticate an owner or approve a threshold. The local hash identifies content; it is not a signature or approval proof.

The source-type rubric describes a **page role** and never determines source officialness or authority. Relevance is an ordered assessment and cannot exclude or erase any evidence; critical identity, occurrence, date, time-zone, venue, edition, status, cancellation, reschedule, permission, and conflicting evidence stays in prepared state. Injection is a presence probability; a missed injection signal cannot grant capabilities or change budgets, tools, approvals, or output boundaries. Identity, fact-support, and conflict outputs are recommendations only and cannot merge, verify, accept, or overwrite facts. Brand-role classification never establishes ownership, association, permission, license, or reproduction rights.

## Preparation interface and limits

`prepareIndependentQuestions(observations)` and `prepareDependentQuestions(observations, predecessorPlan)` accept bounded local records described in `index.d.mts`. Inputs are already privacy-bound text and opaque source references by caller contract. The module cannot authenticate that privacy status, tenant, source reference, visual approval, or language tag. It has a limited credential-pattern rejection guard; this is not a privacy scrubber or a substitute for the upstream privacy boundary. The current privacy boundary exposes reviewed derivative facts rather than general text and is not used here.

Observation prose is untrusted data. The functions read own data properties only, reject getters, custom prototypes, unknown keys, malformed Unicode, duplicate references, and thrown proxy traps, and snapshot the values before hashing. The plan retains every accepted observation and field claim; it sorts records by opaque observation reference to make hashes independent of input order. SHA-256 field, record, state, plan, registry, and definition hashes provide stable change detection, not source authenticity or a signature.

Local hard caps are 32 observations, 4,096 UTF-8 bytes per text field, 10,000 UTF-8 bytes of text total, 16,384 UTF-8 bytes for state, and 32,768 UTF-8 bytes for the whole plan. A predecessor snapshot is separately limited to depth 16, 4,096 nodes, and 131,072 UTF-8 bytes before it is checked. Inputs that exceed a cap are rejected without truncation. These are byte bounds, **not tokenizer guarantees**; no token count is computed. TypeSafe documents a 64k total token limit and a 32k limit for state plus the longest question, so these local limits do not prove a prepared plan fits its model limits. Text is retained as supplied after validation; no model execution occurs here.

Five questions are prepared for independent evaluation. Fact support and conflict require a later call with a new state that has the same source-evidence hash and exactly one caller-supplied completion observation linked by hash to an eligible identity-stage plan. Preparation verifies current registry and state hashes, source record hashes, plan structure, and the predecessor link. It cannot verify that a provider actually ran or that an identity answer is true; completion is marked `caller_asserted_for_preparation_only`. There is no same-batch dependency between identity and its dependent questions.

Every returned plan is immutable and deterministic for the same ordered evidence snapshot. Per-question eligibility and review reasons are included, but every plan remains `readinessStatus: blocked`, `promotionStatus: unpromoted`, and `executionStatus: not_dispatched`. Readiness requires an accepted injected DecisionPort contract, authenticated Agent and research approval, an approved policy, and completed label/metric/corpus reconciliation. This module defines no request, result, usage, receipt, accepted-transport, or promotion schema and makes no routing or served-model claim.

## TypeSafe references checked 2026-10-10

- [API reference](https://docs.typesafe.ai/api): Choice criteria maps options to rubrics; Score criteria is an ordered array of level descriptions; Noul criteria describes true/false. Choice and Score are ordered criteria and classifications here, not acceptance gates.
- [Score primitive](https://docs.typesafe.ai/primitives/score): confirms ordered levels and weighted Score behavior.
- [Noul primitive](https://docs.typesafe.ai/primitives/noul): confirms a yes/no question returns a probability.
- [Models](https://docs.typesafe.ai/models): lists `jev-1.13.0`, text-only input, and English as the primary language where accuracy is best. Other languages require review here; published token limits are not inferred from byte caps.

The model ID is an unaccepted candidate from public documentation, not proof of account eligibility or actual served tier. No provider call or paid evaluation was made.
