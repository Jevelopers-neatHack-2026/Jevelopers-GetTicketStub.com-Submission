# EI-X01 offline candidate compatibility evidence

This bundle runs the pinned shared-contracts research candidate against EI's offline synthetic fixtures. It provides proposal-only compatibility evidence for open issue [EI-X01](https://github.com/Jevelopers-neatHack-2026/event-intelligence/issues/3); it does not change the issue, release gate, runtime imports, accepted schema pins, or release manifest.

The selected shared-contracts snapshot is PR #31 head `b47defaaf630c9d64dcc315c6c4d49fadd194587`, compared with base `686ead140e12b86ce4279b1beea881164025ba6a` and the independently reviewed snapshot `795608ef8d1d91f5fed2dfd77206572adb3970e8`. The PR is still open, draft, and unapproved. `candidate-upstream/audit-inputs/source-pins.json` preserves its source inventory; the runner checks the exact copied source SHA-256 and Git blob IDs before running cases.

`candidate-upstream/schemas/` contains the 12 research schemas and three exact finance-support schemas required by the candidate's synthetic DecisionPort contexts. The added support files are exact b47 bytes, individually pinned in `candidate-upstream/audit-inputs/transitive-dependency-pins.json`. All 550 JSON Schema references in the 15-document closure resolve locally. The broad generated validator bundle and cross-contract test suite are not included. Instead, `candidate-upstream/generated/validators.mjs` is an EI-only adapter that compiles only these raw schemas using test-only Ajv 8.17.1. Its compiler options and `uuid` / Gregorian `utc-time` format expressions match the candidate's pinned `scripts/generate.mjs`; that source is hash- and blob-pinned in the source inventory and is not imported or executed. The candidate runtime, registry, operations, finance-v2 and research-creative helper files remain exact pinned bytes.

`tests/contracts/research-contract-v1/candidate-validation.json` records the expected and actual typed result for every one of the 257 candidate fixture rows. It checks 12 hash-locked fixture manifests, exact error codes and paths, serialization round trips, input immutability, trusted-context fixtures, and zero skipped cases. The separate 20-row `SC-CHK-011` selection exercises exact references and stale digest, unsupported schema version, wrong contract, and wrong revision behavior for `ResearchAnswerReceipt.package_ref`, `EventIntelligencePackage.parent_ref`, `ResearchCorrectionRequest.expected_package_ref`, and `ResearchCorrectionReceipt.new_package_ref`. That selection is a bounded test-harness adaptation of the pinned source matrix; it is not a claim to run the full shared-contracts matrix or approve its findings.

Candidate and EI-X01 semantics remain distinct in the output. This candidate returns `UNSUPPORTED_VERSION`, rejects unknown/additive fields, uses exact semantic-version matching, and advertises no accepted schema versions. EI-X01's proposed acceptance text instead names `UNSUPPORTED_SCHEMA` and requires old-minor/additive compatibility. The runner preserves the candidate's results without aliasing errors or weakening the EI proposal. Those decisions remain with the owner and consumer roles.

All approval, identity, authority, finance and workflow contexts are injected synthetic fixtures. A passing fixture means only that this offline candidate helper matched its pinned expected output. Payload IDs, booleans, fixture references, and synthetic context values do not authenticate a Product issuer, establish current authority or budget, or grant live permission. Unknown, abstain, unavailable, timeout, cancellation and malformed results remain data outcomes. No provider transport or live service is exercised. Commerce, production handoff, and artifact-consumption routes are outside this bundle.

The test harness reuses the pinned candidate helper functions for fixture payload construction, expected-result checks and supported EI modes. It does not import the upstream broad fixture harness because that module imports unrelated commerce, production, capability and historical-finance code. Unknown modes fail the run. Missing inputs, hash drift, unresolved schema references, skipped required rows, and zero case counts also fail the run.

During adapter alignment, an initial run reported 14 date/identifier format failures before the adapter was corrected to the exact pinned generator formats. That first failure output was not saved as a standalone raw log before the adapter edit; it is not reconstructed here and is excluded from the validation evidence. The preserved logs contain the subsequent complete passing run.

After successful validation, `ack-request.json` is prepared with pending statuses for the producer (Agent and research), consumer (Creative and fulfillment), and trusted identity/approval authority (Product and frontend). It is a request packet only; no message is sent and no acknowledgement is recorded. All three roles, the fresh independent review of the exact current candidate, and the remaining issue decisions are pending.
