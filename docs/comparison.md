# FC-09 private quote comparison projection

src/comparison.ts provides an offline, application-facing projection for comparing two or more existing private quote snapshots. Its connector-development-comparison/1 result is private development data. It is not an accepted shared-contract schema, the canonical quote adapter, a root-package consumer integration, or evidence of provider account behavior.

Call comparePrivateQuotes({ entries }, { trustedScope, clock }). Each entry contains only a private quote snapshot and the current catalog/selection request used to recheck it. The function copies strict own-data inputs and calls evaluatePrivateQuoteCurrent for each quote with the supplied trusted scope and one captured clock value. It also normalizes that request's catalog and calls evaluateCatalogSelection to derive current capability fit and region eligibility. The caller cannot set currentness, capability fit, or comparability flags.

The output keeps source entries in their input order. It preserves quote/provider/catalog/selection references, quantity, option/material selections, destination reference and digest, shipping method, exact currency and each amount's original scale, decimal and minor-unit strings, tax basis/reconciliation, provider and local expiry, lead-time range or unknown reason, warning text, and quote-only financial effect. It does not convert money, round, coerce unknown to zero, or treat a known zero as unknown. Currency scale is retained for each quote; scale differences alone do not change the currency basis. No provider-specific SKU, catalog, variant or spec identity is silently mapped to another provider's identifiers.

The result is comparable only when all entries are valid and current, catalog selection is eligible, quote terms do not contain unknown values, and the selected production basis is established and matches. That basis uses exact nanometre geometry and insets plus the selected resolution, surface, file type/count, color space/profile, personalization, and option/material sets. Equivalent length units normalize with integer arithmetic. Options and materials use catalog set semantics for comparison, while their original source order and quote fingerprints remain unchanged. Provider, SKU, variant, catalog, and spec identities are retained as source references; the module does not assume those opaque identities prove or disprove cross-provider equivalence.

Quotes must also agree on currency code, quantity, destination binding, shipping method, tax basis, and expiry semantics. The module preserves exact validity source and timestamps; different values are flagged. Stale, incomplete, invalid, unknown, or out-of-scope entries produce not_comparable or invalid. Quotes from a different tenant/project scope are withheld without exposing their quote IDs, provider references, or terms. A changed catalog or request may leave validated same-scope quote facts visible, but it cannot be marked current or comparable. An unavailable selected-production fact leaves the basis unknown and prevents comparability.

Catalog capability fit and region suitability are evaluator results for the supplied current catalog and selection. They are not business rankings or a guarantee that an order will be accepted. Lead-time values remain estimates, with their source quote and provider reference retained; they are never promised delivery dates. Warning text is copied only after the existing quote validator has screened it. Tenant/project identifiers, raw addresses, contact details, credentials, URLs, provider errors, and provider notes are not included in the projection.

The module has no ranking, recommendation, winner, selection, mutation, quote, submit, order, payment, budget, finance, provider-network, or shared-contract write operation. It derives no authorization. Its financialEffect is always quote_only. Synthetic quotes and injected quote boundary validation remain test fixtures. The projection keeps the private quote and catalog source references but does not claim canonical consumer conformance; shared-contracts #25 and application consumer review remain pending.

Run the standalone fixture suite after the normal local build:

    npm run build
    node tests/comparison-suite.mjs

The suite checks equivalent distinct-provider selections across exact unit representations; geometry, surface, personalization, bleed/safe-area, resolution, file and color differences; option/material set ordering and membership; exact amount preservation including scale differences and known zero; explicit unknown/stale/incomplete states; recalculated capability and region outcomes; scope privacy; serialization; hostile input handling; immutability; absence of ranking; and zero quote/order calls during projection. Its network-control case proves local loopback in a normal process. When FC_COMPARISON_EXPECT_NETWORK_DENIAL=1, it instead asserts that the operating-system policy rejects a local socket with EPERM; run that variant under an actual network-denying OS sandbox to collect that evidence.
