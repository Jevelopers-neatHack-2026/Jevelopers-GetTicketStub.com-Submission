# Prepare the owned execution target before reservation

Creative Engine owns image target construction in `src/models/image-adapter-core.mjs` and decision target construction in `src/contracts/decision-port/v1.mjs`. Hosts inject credentials and independent authority ports; they must use these owned targets rather than copy the hashing or provider serialization into application code. Preparation does not select a production model, authenticate an account, reserve funds, resolve credentials, or dispatch a provider request.

Both native image providers expose `prepareAttempt(input)`. Supply the real allocated metered attempt, operation, trusted scope, actor/job, brief, plan, parent and optional reference manifests, decision result, abort signal and deadline. The method snapshots bounded plain JSON, validates the pinned operation/configuration, renders the real prompt, and reads and validates scoped immutable image inputs. It returns `{ token, target_binding, target_binding_sha256, deadline_at }`. Prompt text and image buffers stay private to the provider instance.

Pass this exact return value as `prepared_attempt` to the same provider's `generate` or `edit` call. The provider consumes its private, process-local token before authority callbacks. Forged or copied tokens, another provider instance or operation, replay, changed immutable input, a different signal, and a changed or expired deadline fail. Dispatch uses the already prepared prompt and bytes and still requires the actual reservation, dispatch intent and transport identity, current capability/access/Finance checks, post-ACK revalidation, and the final owner fence. Preparation grants no dispatch authority.

The runtime prepares native generate, edit and concept attempts before C03. `executeCreativeMeteredAttempt` accepts an optional `executionTarget: { target_binding, target_binding_sha256, deadline_at }`, snapshots it, and allocates the one transport identity before admission. Its metering proxy calls `reserveAttempt(attempt, { ...executionTarget, transport_attempt_id })`. The exact allocated identity is reused for reservation capture, transport acknowledgement and dispatch; a target-bound execution cannot introduce a second identity. This second argument is optional for existing metering consumers. A deployed bridge that requires exact target admission must require it and retain the admitted target under its own Finance/access authority.

`decisionExecutionTarget(request, { trustedScope })` returns the versioned `DecisionExecutionTarget` wrapper, and `decisionExecutionTargetHash` hashes that wrapper canonically. Its request contains every immutable canonical DecisionPort field except the eventual `budget_ref.reservation_ref`. Reservation-free preparation requires separately supplied trusted scope and permits only that omission. A final full canonical request can be hashed with the same helper; its actual reservation is still validated before exclusion. `validateDecisionRequest` and the JEV dispatch boundary continue to require the real reservation. Event/request IDs, timestamps, deadline, attempt identity, policy, state and questions are allocated once before admission and remain bound afterward.

Normal and inspection DecisionPort consumers pass `target_binding_sha256` separately from the canonical request and result, together with `revalidateDispatch`, transport acknowledgement, and `assertDispatchCurrent`. The ordinary `DecisionPortResult` gains no target field. Usage mapping uses the prepared execution target rather than inferring one from a provider response.

Inspection has explicit `prepareInspectionDecisionPlan`, `prepareInspectionEvidenceBatch`, `prepareInspectionRouteBatch`, and `bindInspectionDecisionReservation` APIs. Binding accepts the exact module-prepared request once and adds only the actual admitted reservation. Prepared plan provenance stays stable through binding. Durable stages containing a prepared target retain that reconstruction path during recovery; historical stages retain the existing reserved-context path. The process-local image token cannot be restored after restart. Existing durable job, attempt and observation state controls recovery: an in-flight or unknown outcome retains its hold and cannot become an automatic paid redispatch. Unknown usage and unconfirmed settlement still prevent artifact publication.

For migration, deploy this producer revision before a host begins requiring target-bound admission. Existing providers without preparation and metering implementations accepting one argument remain usable. Direct callers of native `generate`/`edit` without a token retain their existing full-reservation input contract and prepare internally; that compatibility path does not supply pre-reservation admission data to a strict host bridge. Applications should expose the real native provider's preparation method and pin the tested Creative Engine revision. No environment variable or subscription preference replaces credential, capability, authorization or Finance evidence.
