# Controlled retrieval module

This package provides an internal retrieval primitive, not the product's accepted research API. `@jevelopers/event-intelligence-safe-retrieval` is private and its exports describe only the current module boundary. No shared `ResearchRequest` or consumer approval contract is defined here. EI-01 (#7) and EI-09 (#9) integration remains outstanding, so this implementation alone does not satisfy or close EI-02 (#8).

The production fetcher accepts only HTTP(S) URLs, has no API for caller-supplied headers, and never uses environment proxy settings, cookies, browser execution, JavaScript, or parser-side network fetching. It validates the hostname, resolves A/AAAA records through a bounded DNS wire client, examines CNAME links, rejects any unsafe alias or address, and connects directly to one of the approved numeric addresses. HTTP redirects pass through the same checks. HTTPS keeps the original URL hostname for certificate verification and checks the connected peer address against the pinned result. Special-purpose prefixes are denied conservatively, including service prefixes even when their registry metadata marks them globally reachable; the underlying address registries are [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry) and [IANA IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry), whose entries can change and need review when this policy is updated.

The immutable baseline is 30 network requests per `SafeFetcher` instance, five redirects per fetch, four concurrent fetches, a 10-second connection limit, a 30-second total deadline, 10 MiB of encoded response bytes per request, 20 MiB of decoded text/JSON, 10 MiB for image or PDF intake, and 100 MiB decoded aggregate bytes per instance. The application must create and retain one instance for a research run; this module does not enforce a cross-instance or tenant quota. Images must expose dimensions no larger than 10,000 by 10,000 and 20 megapixels. The module accepts HTML/XHTML, UTF-8 text, JSON/JSON-LD, PDF, PNG, JPEG, WebP, and GIF after MIME and signature checks. Unsupported encodings and media fail closed. Only complete HTTP 200 responses are accepted.

These are intake limits, not proof that downstream decoders are safe. The image/PDF parser handoff must independently enforce memory, dimension/page, embedded-resource, and side-network-fetch limits before those formats are treated as supported in an integrated product. This package currently returns bounded bytes; it does not parse HTML, image, or PDF content and does not persist extracted evidence.

The deterministic integration fixtures use loopback sockets behind a private test-only seam that is not in the package export map. That seam is not a production allowlist or security bypass. Tests establish behavior at the HTTP/TLS/DNS socket boundary locally; they do not establish external egress telemetry, infrastructure firewall behavior, production resolver behavior in every environment, or any live/provider behavior. The runner reports external egress as “not measured.”

The supported production major is Node 22, with the representative patch pinned to 22.23.3 in `.node-version`, `.nvmrc`, and CI; `package.json` constrains the supported major to `>=22 <23`. The local development shell has Node 24.15.0, which is not evidence of Node 22 compatibility. The Node 22 verification binary was installed from the official archive after matching its SHA-256 against the published checksum list; local tests use the macOS arm64 build. CI uses Ubuntu 24.04, but that does not certify the reported CloudLinux/CageFS x86_64 server running kernel 4.18. The reported 12 CPUs and 70.26 GiB are host-wide figures and do not establish a tenant's LVE quota; this module makes no quota assumption. No production host connection or deployment is authorized or performed. Runtime code uses only Node built-ins. TypeScript and `@types/node` 22 are pinned development-only tools, and a real consumer import is checked against the package declarations.

## Verification

Run `npm ci`, `make verify CASE=safe-retrieval MODE=mock`, `npm run test:runner`, and `npm run typecheck`. The mock case only uses local deterministic fixtures. Reserved `content-privacy`, `evals`, and `research-api` routes fail if their test files are absent; their success is not inferred from this module's tests. `MODE=live` is unconditionally blocked in this internal package. A config-shaped file is reported as descriptive presence only, never as authenticated approval; no provider request is made.
