# Controlled retrieval module

This package provides an internal retrieval primitive, not the product's accepted research API. `@jevelopers/event-intelligence-safe-retrieval` is private and its exports describe only the current module boundary. No shared `ResearchRequest` or consumer approval contract is defined here. EI-01 (#7) and EI-09 (#9) integration remains outstanding, so this implementation alone does not satisfy or close EI-02 (#8).

The production fetcher accepts only HTTP(S) URLs, has no API for caller-supplied headers, and never uses environment proxy settings, cookies, browser execution, JavaScript, or parser-side network fetching. It validates the hostname, resolves A/AAAA records through a bounded DNS wire client, examines CNAME links, rejects any unsafe alias or address, and connects directly to one of the approved numeric addresses. HTTP redirects pass through the same checks. HTTPS keeps the original URL hostname for certificate verification and checks the connected peer address against the pinned result. Special-purpose prefixes are denied conservatively, including service prefixes even when their registry metadata marks them globally reachable; the underlying address registries are [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry) and [IANA IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry), whose entries can change and need review when this policy is updated.

The DNS UDP client handles Node's asynchronous connect-error callback before attempting a send. A failed connection or synchronous socket failure closes the query and returns a sanitized `DNS_FAILURE`, allowing the existing configured-nameserver fallback within the original deadline. UDP and TCP connect callbacks arriving after settlement or cancellation cannot send; they also check the absolute deadline before sending, even when the deadline timer has not run yet. A truncated UDP response becomes usable only after its TCP fallback validates completely. A failed TCP response cannot silently become an empty address-family result alongside a valid result from the other family. Local regression controls use native sockets, a native address block list and explicit callback timing to verify failure, cleanup and loopback recovery. They do not establish the underlying cause of an external connection failure or prove that an execution environment permits production DNS/HTTP egress.

The immutable baseline is 30 network requests per `SafeFetcher` instance, five redirects per fetch, four concurrent fetches, a 10-second connection limit, a 30-second total deadline, 10 MiB of encoded response bytes per request, 20 MiB of decoded text/JSON, 10 MiB for image or PDF intake, and 100 MiB decoded aggregate bytes per instance. The application must create and retain one instance for a research run; this module does not enforce a cross-instance or tenant quota. Images must expose dimensions no larger than 10,000 by 10,000 and 20 megapixels. The module accepts HTML/XHTML, UTF-8 text, JSON/JSON-LD, PDF, PNG, JPEG, WebP, and GIF after MIME and signature checks. Unsupported encodings and media fail closed. Only complete HTTP 200 responses are accepted.

Response `Content-Type` is checked before body decoding. Exactly one header field is required; duplicate fields, combined values, and malformed parameters return the existing sanitized `UNSUPPORTED_MEDIA` error. Parameters use the token, double-quoted string, quoted-pair, and empty-segment rules in [RFC 9110 sections 5.6.4 and 5.6.6](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.6.4). For textual formats (HTML, XHTML, plain text, JSON, JSON-LD, and the separate SVG mode), an explicit charset must be a single case-insensitive `utf-8` or `utf8` value. Unsupported, empty, duplicate, extended, or continued charset declarations are rejected instead of being erased and then interpreted as UTF-8. No transcoding or charset guessing is added. Valid unrelated parameters remain accepted, including quoted semicolons and escapes; binary PDF/image handling is unchanged. Returned documents keep their historical base `contentType` string. The rejection records the existing `content_type_rejected` lifecycle outcome with no body decode or completion; it still follows an actual request and response and does not imply zero provider cost. These checks preserve source interpretation, and confer no authority or trust on the host or its content.

`SafeFetcher.fetchSvgAsset` is a separate narrow mode for the internal opt-in local acquisition path. It accepts a single `image/svg+xml` response up to 128 KiB and does not follow redirects or request subresources. It returns actual bounded response bytes; it does not inspect or sanitize them, persist evidence, or grant policy, rights, ownership, or role claims. The private retrieval integration binds this one-hop request to a current stored asset-source candidate, inspects the response bytes independently, and records raw and transformed bytes as separate encrypted evidence. Ordinary `fetch` remains closed to SVG.

Acquisition remains default-off and uses the same durable frontier, deadline, admission count, and byte budget as ordinary retrieval. An opted-in host supplies both the policy callback and a release-authority issuer. The issuer calls `createPrivateAssetReleaseAuthority` with its authenticated tenant, the run and normalized policy it receives, and the provided monotonic deadline; it retains the returned controller and synchronously revokes it whenever any bound authority changes. The opaque controller is tied to the exact tenant, run, policy digest, deadline, and store-selected candidate set. Before a blocked local plan is included in the final draft, retrieval reopens the current source candidate and both role-separated encrypted records, checks them against the final selected source snapshot, then performs the last awaited current-policy refresh. The store returns an opaque single-use check; `finalizeControlledAssetRelease` synchronously checks current store authorization and persisted selected evidence/facts/retention, then invokes the bounded draft projection in that same call stack. No awaited or external callback follows projection. A synchronous revocation before projection denies release; a queued revocation after projection returns `after_release` and does not retroactively change the result. The zero-plan path still runs the final selected fact/source check. This protocol serializes supported in-process callbacks; it requires host revocation wiring and is not a sandbox for independently mutated authority in another process. The declarations keep the historical `EvidenceStore` port usable for default-off callers; `ControlledAssetEvidenceStore` is the additive capability returned by `createEvidenceStore` and required by the opt-in input type. Existing callers that enable SVG acquisition must add `assetAcquisitionReleaseAuthorityFor` and retain/revoke its controller. These plans remain `blocked_local_inspection_only`, with rights and permission unknown and no external asset version accepted.

These are intake limits, not proof that downstream decoders are safe. The image/PDF parser handoff must independently enforce memory, dimension/page, embedded-resource, and side-network-fetch limits before those formats are treated as supported in an integrated product. This package currently returns bounded bytes; it does not parse HTML, image, or PDF content and does not persist extracted evidence.

The deterministic integration fixtures use loopback sockets behind a private test-only seam that is not in the package export map. That seam is not a production allowlist or security bypass. Tests establish behavior at the HTTP/TLS/DNS socket boundary locally; they do not establish external egress telemetry, infrastructure firewall behavior, production resolver behavior in every environment, or any live/provider behavior. The runner reports external egress as “not measured.”

The supported production major is Node 22, with the representative patch pinned to 22.23.3 in `.node-version`, `.nvmrc`, and CI; `package.json` constrains the supported major to `>=22 <23`. The local development shell has Node 24.15.0, which is not evidence of Node 22 compatibility. The Node 22 verification binary was installed from the official archive after matching its SHA-256 against the published checksum list; local tests use the macOS arm64 build. CI uses Ubuntu 24.04, but that does not certify the reported CloudLinux/CageFS x86_64 server running kernel 4.18. The reported 12 CPUs and 70.26 GiB are host-wide figures and do not establish a tenant's LVE quota; this module makes no quota assumption. No production host connection or deployment is authorized or performed. Runtime code uses only Node built-ins. TypeScript and `@types/node` 22 are pinned development-only tools, and a real consumer import is checked against the package declarations.

## Verification

Run `npm ci`, `make verify CASE=safe-retrieval MODE=mock`, `npm run test:runner`, and `npm run typecheck`. The mock case only uses local deterministic fixtures. Reserved `content-privacy`, `evals`, and `research-api` routes fail if their test files are absent; their success is not inferred from this module's tests. `MODE=live` is unconditionally blocked in this internal package. A config-shaped file is reported as descriptive presence only, never as authenticated approval; no provider request is made.
