# Collateral handoff and receiver procedure

`v0.1.0-rehearsal` is an internal draft package for concept collateral. It does not grant publication rights, constitute an approved release, or meet the neatHack submission demo requirement. The versioned `package-spec.json` is the source list; `tools/package_collateral.py` binds each selected source/export, copy, alt text, scene, selected claim/CTA, provenance record, brand reference, and evidence file to exact SHA-256 hashes and source pins. Every package copy and contextual HTML dependency also names its own inventory/provenance join, exact content pin, and destination scope; the receiver validator rejects a missing or stale join. The committed 150-second silent synthetic rehearsal, SRT/VTT, transcript, HTML and exact author receipt are current inputs, but do not satisfy the absent final product demo at `demo/exports/v1-demo.mp4`. Never insert a guessed path, checksum, approval, or source commit.

## Naming and legacy-file mapping

New package copies use this deterministic form:

```text
{family}-{assetId}-{revision}-{destination}-{dimensions}-{locale}-{variant}.{extension}
```

For example, the existing `demo/recording-checklist.md` source maps to `demo-001-demo-recording-checklist-001-r02-repository-internal-review-text-en-us-rehearsal-recording-plan.md`. A visual source and its export keep the same asset ID but have distinct variants and extensions. A dynamic rehearsal MP4 and its SRT/VTT sidecars receive distinct role and format records, exact hashes, scene references, and receipt checks. The `text` dimension token means dimensions do not apply; raster/video dimensions come from the actual bytes and are never inferred from a filename.

The older working names remain intact and are source paths, not release names. Existing r01 package-copy names remain immutable; the current rehearsal rebuild uses r02 after source text changed:

| Existing source path | Stable package asset ID | Package role |
| --- | --- | --- |
| `demo/diagrams/demo-workflow.svg` and `.png` | `DEMO-WORKFLOW-DIAGRAM-001` | Editable vector and rendered export |
| `demo/screenshots/synthetic-stub-mockup.svg` and `.png` | `DEMO-SCREENSHOT-SET-001` | Clearly labeled fictional concept artwork |

Existing release directories and files are retained. The builder copies exact source bytes into `release/{version}/assets/`, except the responsive HTML entrypoint and its contextual dependencies: the entrypoint is under `view/demo/deck/`, with the original relative `src` and `href` targets at `view/demo/diagrams/`. The manifest names every local HTML reference, its source path, SHA-256 and source commit, resolved relative target, and contextual copy. The validator re-resolves those references, rejects package-root traversal, and checks each context copy's exact bytes and pin. Open the HTML from its versioned `view/demo/deck/` path so `../diagrams/demo-workflow.svg` and `../diagrams/demo-workflow-alt-text.md` resolve inside the package. The source HTML bytes are preserved unchanged. An existing target is accepted only when its SHA-256 is identical. A different byte sequence at the same target fails. Increase the asset revision or package version and preserve the prior version; never use a “final-final” suffix or rewrite a legacy source in place. While a package is explicitly `draft_rehearsal_only`, the generated manifest may be refreshed as claims, receipts, or review inputs change; the prior manifest is preserved under `release/{version}/history/manifest-{content-hash}.json` before the draft manifest is replaced. Asset copies remain immutable under their current revision. A non-draft or approved manifest cannot be replaced by this builder; issue a new version through an owner-reviewed release process.

## Receiver verification

Start from the reviewed delivery commit that contains the exact manifest, package copies, and inventory/provenance joins being received. Select an asset by all of its stable fields, not by whichever file looks newest. `candidateSourceCommitAtGeneration` names the separate input snapshot used to reproduce that delivery; its manifest is the pre-build draft, so do not use that older snapshot as the receiver's starting checkout. For example:

```sh
jq '.assets[] | select(.assetId == "DEMO-WORKFLOW-DIAGRAM-001" and .variant == "concept-workflow-presentation-png") | {file, source, packageCopy, accessibleAlternative, sceneIds, claimReferences, provenance, destinations, approval, limitations}' release/v0.1.0-rehearsal/manifest.json
jq '.assets[] | select(.assetId == "DEMO-DECK-SUPPORT-001") | {packageCopy, compositionDependencies, compositionReferenceErrors, accessibleAlternative, claimReferences, provenance, limitations}' release/v0.1.0-rehearsal/manifest.json
python3 tools/package_collateral.py validate release/v0.1.0-rehearsal/manifest.json
sha256sum release/v0.1.0-rehearsal/assets/<selected-package-filename>
git show <sourceCommitId>:<source-path> | sha256sum
```

Compare both digests with the selected manifest row. When the manifest records a content-digest source pin, compare that digest with the exact local source bytes instead of assuming a Git commit pin. Open the exact package copy in a native viewer; compare it with the source/export and inspect its dimensions, crop, concept label, embedded metadata, and readability. Read the linked alt text or transcript, then check the exact selected claims and qualifiers, provenance scope/expiry, permitted destination, brand decision, and reviewer/date in the manifest. A checksum proves byte identity only; it does not prove rights, accessibility, factual support, or approval. Reject any path whose status is missing, modified, stale, pending, expired, revoked, superseded, out of scope, or unjoined.

For the HTML support page, open the manifest-selected `packageCopy.path` within `release/v0.1.0-rehearsal/`. Keep its declared contextual dependencies at their package-relative paths; opening only the renamed HTML file from `assets/` loses its required relative references. The package validator verifies the exact composition dependencies and path containment.

Reproduce the package from the exact input commit named by `candidateSourceCommitAtGeneration`, in a detached worktree outside your active checkout. The documented `bind-self-reference` step is part of reproduction because a freshly rebuilt draft has a new exact manifest digest; it updates only the explicitly projected digest references: the manifest hash/revision/url tuple, plus the exact inventory file digest pair that changes when the manifest hash is written into the inventory. The inventory digest pair's URL remains unchanged and bound.

```sh
SOURCE_COMMIT=$(jq -r '.candidateSourceCommitAtGeneration' release/v0.1.0-rehearsal/manifest.json)
REPRO_DIR=$(mktemp -d)/source
git worktree add --detach "$REPRO_DIR" "$SOURCE_COMMIT"
python3 "$REPRO_DIR/tools/package_collateral.py" build --root "$REPRO_DIR" --version v0.1.0-rehearsal
python3 "$REPRO_DIR/tools/package_collateral.py" bind-self-reference --root "$REPRO_DIR" --version v0.1.0-rehearsal
python3 "$REPRO_DIR/tools/package_collateral.py" validate --root "$REPRO_DIR" "$REPRO_DIR/release/v0.1.0-rehearsal/manifest.json"
python3 "$REPRO_DIR/tools/validate_collateral.py" --mode draft
cmp release/v0.1.0-rehearsal/manifest.json "$REPRO_DIR/release/v0.1.0-rehearsal/manifest.json"
git worktree remove --force "$REPRO_DIR"
```

`cmp` should report byte-identical manifests for the same committed inputs. The `validate` command also rebuilds the authoritative manifest from the current specification and policy snapshot, rejects omitted, duplicated, or altered records, and checks every source, package copy, sidecar, and contextual HTML dependency against it. It verifies that `candidateSourceCommitAtGeneration` is an existing ancestor and that the commit contains each exact bound source/copy byte; projected inventory/provenance inputs use the same explicitly declared semantic-field binding. Validation must pass before comparing manifests. Run these commands before removing the isolated worktree; remove its empty temporary parent directory separately. The tool uses Python's standard library plus `ffprobe` to inspect actual video metadata and makes no network or paid-provider calls. Keep the recorded ffmpeg/ffprobe, Chrome, Node, Python, and Pillow versions with the render receipt. Browser version, OS, font fallback, font rasterization, and glyph metrics can change exported pixels and hashes. Re-rendered bytes are a new revision and require another visual and accessibility inspection; do not treat a matching source SVG or HTML hash as proof that a PNG still matches.

The manifest also binds the canonical policy inputs that readiness reads directly: the validator source, synthetic canary fixture, and rehearsal render plan. Its `sourceDiscovery` record uses `git-tree-recursive-regular-files-by-root-and-extension-v1` to list the sorted tracked regular-file set beneath each configured video, caption, and rehearsal-evidence root. Validation compares those sets with the recorded source commit, so a candidate-only receipt, caption, video, or evidence file cannot disappear from the rebuilt manifest unnoticed. In addition, validation reads `docs/collateral-inventory.json` from that commit, compares its complete `trackedFiles` path set with the commit tree, and checks each ordinary tracked-file SHA-256 against the candidate blob. The candidate-time manifest, inventory, and claims digest joins are checked against that source commit; the candidate inventory/provenance self-reference fields remain covered by the manifest's narrowly declared semantic projections. Present source facts bind their exact SHA-256; explicitly missing source facts must also be absent from the recorded commit. This proves the enumerated input snapshot for reproduction, not a signed build attestation or an approval decision.

The validator reports integrity separately from readiness. A draft manifest may have matching checksums while its collateral or external submission gate remains `BLOCKED`. Policy support files `docs/collateral-inventory.json` and `review/provenance.json` use the `sha256-canonical-json-self-reference-projection-v2` canonical JSON semantic-field binding: sorted-key compact UTF-8 JSON is hashed after omitting only `trackedFiles[path=release/v0.1.0-rehearsal/manifest.json].sha256`, `.trackedAtRevision`, `records[assetId=HANDOFF-MANIFEST-001].source.revision`, `.source.url`, `.checksum.value`, `records[assetId=PROV-FILE-E018FDB8D981].source.revision`, and `.checksum.value`. The provenance `source.url` for the inventory record remains bound. JSON whitespace is not bound. Every other inventory/provenance field remains bound, including rights, claim, copy and evidence joins. The second narrow selector breaks the transitive self-reference: the manifest hash updates the inventory row, which updates the inventory file digest recorded by its provenance row. Both digests remain checked against current bytes by canonical `validate_all` before readiness is evaluated; the projection does not relax that exact check. The manifest's exact SHA-256 is recorded in the inventory row and `HANDOFF-MANIFEST-001` provenance checksum and as the `sha256:<digest>` content revision. The exact current inventory SHA-256 is recorded by `PROV-FILE-E018FDB8D981`; its URL stays null and bound. The same projection descriptor and digest appear in both `supportFiles` and `policyInputHashes`; unsupported or missing algorithms/selectors fail closed.

For visual rendering reproduction, use Python 3.9.6 with Pillow 11.3.0 and record Chrome, Node, ffmpeg and ffprobe versions alongside the render receipt. The package builder itself uses the Python standard library plus `ffprobe`. Select an interpreter by checking `python3 --version` and `python3 -c 'import PIL; print(PIL.__version__)'`; do not assume a system-default Python has Pillow. No host-specific interpreter path is part of the package. Exact manifest regeneration is source-commit-sensitive because the manifest records `candidateSourceCommitAtGeneration`; reproduce from that recorded input commit in an isolated clean worktree, not by rebuilding over the delivered control files. After the draft is built in that isolated worktree, run `bind-self-reference` to refresh only the manifest checksum fields named in the documented canonical JSON projection, then validate both package integrity and global policy joins. This local binding does not approve or publish the draft. The manifest and release-review `Astra` pending status reflect the receiver state at generation time. Check the durable [PR #14 review thread](https://github.com/Jevelopers-neatHack-2026/marketing-material/pull/14) for any later review of the exact delivery commit and its recorded base/head; keep that receipt external to the immutable manifest. Independent review does not approve publication or clear producer-owned external gates.

Do not override a gate, approve an asset from a model review, upload/post automatically, or treat a rehearsal as product evidence.
